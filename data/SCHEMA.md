# sorcmerc data catalog — schema (F1 output)

Generated by `dnd-maintainer/scripts/export-sorcmerc.mjs`.
Regenerate: `cd ~/dnd-maintainer && npm run export:sorcmerc`

Source: D&D 2024 PHB data in `dnd-maintainer/src/lib/sources/*.ts` + `src/lib/dnd-helpers.ts`,
prose from `src/locales/en/gamedata.json`. All files pretty-printed, 2-space, trailing newline.

Every `id` is a stable kebab-case (or lowercase, for skills/subclasses) key. Cross-file
references use these ids (e.g. `classes[].levels[].grants[].featId` → `feats[].id`).

---

## The grant vocabulary (READ THIS — F2 depends on it)

`classes.levels[]`, `subclasses.levels[].grants`, `species.traits`, `species.lineages[].grants`,
`backgrounds.grants`, `feats.grants`, `fighting-styles.grants` all contain **grant arrays** in
dnd-maintainer's native shape, emitted **verbatim**. A grant is `{ "type": <tag>, ... }`.
The GDScript resolver port must handle each `type`:

| type | payload | meaning |
|---|---|---|
| `hit-die` | `die` (4/6/8/10/12) | class hit die |
| `ability-bonus` | `ability`, `bonus` | flat ability increase |
| `ability-choice` | `key`, `count`, `bonus`, `from` (ability list \| null) | player picks abilities to bump |
| `asi` | `key`, `points`, `from` (list \| null = any) | Ability Score Improvement pool (backgrounds use points=3; class ASI levels use points=2) |
| `proficiency` | `category` (`armor`\|`weapon`\|`tool`\|`skill`\|`saving-throw`\|`language`), `id` | fixed proficiency |
| `proficiency-choice` | `category`, `key`, `count`, `from` (id list \| null = any) | player picks proficiencies |
| `skill-expertise` | `skill` | fixed expertise |
| `expertise-choice` | `key`, `count`, `from` (skill list \| null), `fromTools` | player picks expertise |
| `feature` | `feature` `{ id, name?, description?, usesPerRest?, usesCount?, saveDC? }` | named class/species feature. Prose keyed by `feature.id` — see "feature prose" below |
| `feature-choice` | `key`, `options[]` `{ optionId, featureId, grants[] }` | player picks one option; its nested grants apply |
| `speed` | `mode` (`walk`\|`fly`\|`swim`\|`climb`\|`burrow`), `value` (number \| `"walk-equivalent"`), `condition?` | movement |
| `hp-bonus` | `perLevel` | +HP per character level (Dwarf, Tough) |
| `resistance` | `damageType` | damage resistance |
| `armor-class` | `calculation` `{ mode: "armored" }` \| `{ mode:"unarmored", formula:"barbarian"\|"monk"\|"dance" }` \| `{ mode:"natural", baseAc }` | AC formula |
| `ac-bonus` | `bonus` | flat +AC |
| `spellcasting` | `ability`, `source` (`class`\|`species`\|`feat`) | marks a spellcasting origin |
| `spell` | `spellId`, `alwaysPrepared`, `minClassLevel?`, `ability?` | a specific granted spell |
| `spell-choice` | `key`, `count`, `spellList` (classId), `spellLevel` (0-9) | player picks N spells of a level from a class list |
| `feat` | `featId` | fixed feat grant |
| `feat-choice` | `key`, `from` (featId list \| null), `category` | player picks a feat |
| `subclass` | `classId`, `key` | the subclass-selection point (usually class level 3) |
| `fighting-style-choice` | `key`, `count`, `from` (styleId list) | player picks fighting style(s) |
| `weapon-mastery-choice` | `key`, `count` | player picks weapon masteries |
| `damage-choice` | `key`, `count`, `from` (damageType list), `featureIdPrefix` | picks a damage type; expands to `feature` id `${prefix}-${type}` |
| `bundle-choice` | `key`, `category`, `bundleIds` | starting-equipment loadout choice (**not exported as data — see gap**) |
| `lineage-choice` | `key`, `speciesId`, `from` (lineage id list) | species sub-lineage pick; grants in `species.lineages[]` |
| `resource-pool` | `poolId`, `max`, `regen`, `dieSizeSteps?` | a limited-use resource (Rage, Ki, Channel Divinity, Sorcery Points…) |

`key` is a `ChoiceKey`: `"<category>:<origin>:<id>:<index>"`, origin ∈ species/background/class/subclass/feat.
It's the stable slot a player's decision is stored against — keep it.

### `resource-pool.max` modes
- `{ mode:"fixed", value }`
- `{ mode:"class-level", classId }` — max = level in that class
- `{ mode:"class-level-plus", classId, offset }` — max = class level + offset (clamped ≥0)
- `{ mode:"proficiency-bonus", classId }` — max = PB derived from that class's level
- `{ mode:"level-steps", classId, steps:[{minLevel,value}…] }` — highest satisfied `minLevel` wins (e.g. Rage: 2/3/4/5/6)

### `resource-pool.regen`
`"short-rest"` | `"long-rest"` | `{ mode:"compound", shortRestAmount }` (all on long rest, N on short).

### `resource-pool.dieSizeSteps` (optional)
`[{minLevel, dieSize}]` — scaling die for Psionic Energy etc. (d6→d8→d10→d12).

### feature prose
`feature` grants carry only an `id` (+ optional inline fields). Human-readable name/description
live in `dnd-maintainer/src/locales/en/gamedata.json` under `features.<id>` (430 entries).
**Not currently re-exported** — if F2/T-series need feature tooltips, add a `features.json`
dump to the export script (one line). Same for `resourcePools.<poolId>` prose.

## classes.json — array, 12 records

```
{
  "id": "barbarian",
  "name": "Barbarian",
  "primaryAbility": "str",
  "hitDie": 12,
  "savingThrows": ["str", "con"],
  "spellcastingAbility": null,          // or "int"/"wis"/"cha"
  "armorProficiencies": ["light","medium","shields"],
  "weaponProficiencies": ["simple","martial"],
  "toolProficiencies": [],
  "toolChoices": null,                  // or { count, from:[toolId…] } (Bard)
  "skillChoice": { "count": 2, "from": ["athletics", …] },   // from:null = any skill (Bard/Rogue-ish)
  "quickBuild": null,                   // or { highestAbility:[…], secondaryAbility, suggestedBackground }
  "spellSlots": [ [], [], …20 entries… ],   // index 0 = char level 1. Each = slots by spell level [L1,L2,…]. [] = none.
  "pactMagic": null,                    // warlock only: 20 entries of { count, slotLevel }
  "levels": [ [ <grant>, … ], … 20 arrays … ]   // index 0 = level 1 … index 19 = level 20
}
```

`spellSlots` come from dnd-maintainer's full/half-caster tables (`getSpellSlots`). Subclass
casters (Eldritch Knight, Arcane Trickster) get **no** entries here — their progression is in
`subclasses.json` grants only (dnd-maintainer models it as feature grants, not a slot table — **gap**, see below).
`levels[i]` lists every grant gained *at* that level (ASI grants appear at 4/8/12/16/19, the
`subclass` grant at level 3, etc.).

## subclasses.json — array, 48 records (4 per class)

```
{
  "id": "berserker",
  "name": "Path of the Berserker",
  "description": "For some Barbarians, rage is a means to an end…",
  "classId": "barbarian",
  "levels": [ { "classLevel": 3, "grants": [ <grant>, … ] }, { "classLevel": 6, "grants": […] }, … ]
```

## Gaps (data genuinely absent in dnd-maintainer — not invented here)

1. **Background starting equipment & gold** — `backgrounds.json.startingEquipment` / `.startingGold`
   always `null`. dnd-maintainer models backgrounds only as grants (ability/skill/tool/feat);
   the 2024 "Equipment: choice of A or 50 GP" line is not in its data. T6 (merchant/rest) and
   T1 (creator equipment step) must source this elsewhere or hardcode.
2. **Class/background starting-equipment loadouts** — `bundle-choice` grants reference
   `bundleIds` (e.g. `"barbarian-loadout"`) whose contents live in `dnd-maintainer/src/lib/sources/bundles.ts`
   and are **not exported**. Add a `bundles.json` dump if T1 needs it (small).
3. **Spell mechanical fields** — `SpellDef` in dnd-maintainer carries **no** structured
   damage/save/area/scaling; only level/school/time/range/components/duration/concentration/ritual/classes.
   `spells.json.mechanics` is a **regex extraction from the English prose** in this script
   (`parseMechanics`). It handles the common SRD phrasings well (`NdM <type> damage`,
   `<Ability> saving throw`, `ranged/melee spell attack`, `N-foot Sphere/Cone/Line/…`,
   `regains NdM Hit Points`, `<Condition> condition`, "half as much on a success", upcast
   sentence). 65/146 spells matched nothing (utility spells, or phrasings outside the patterns).
   **F3 must treat `mechanics` as a hint, not authoritative** — spot-check against `description`,
   and expect to hand-fill combat-relevant spells.
4. **Feature / resource-pool prose** — `feature` grant ids and `resource-pool` poolIds are
   emitted, but their names/descriptions (in `gamedata.json` `features.*` / `resourcePools.*`)
   are not re-dumped. Trivial to add if needed.
5. **Subclass spell-slot progression** — third-caster subclasses (Eldritch Knight, Arcane
   Trickster) have their casting modeled as feature grants in `subclasses.json`, with **no**
   slot table. `classes.json.spellSlots` is empty for fighter/rogue. F2 needs the 2024
   third-caster table hardcoded (it's a fixed 4-row progression).
6. **Multiclassing** — every level-keyed resolver mode assumes single-class. Plan defaults to
   single-class anyway.
7. **Spell → class availability** is native lists only (`nativeClasses`). Subclass "expanded
   spell list" / always-prepared spells appear as `spell` grants inside `subclasses.json`, not
   in `spells.json.classes`.
